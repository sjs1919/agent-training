## 一、业务架构

**行业**：3D 打印服务（按需制造），公司约 300 人，A 轮→业务成熟完整周期

**业务定位**：统一管理多品牌、多类型生产设备的智能调度与执行系统，是公司从"人工盯电话"到"7×24 无人值守"的核心基础设施

**业务规模**：
- 设备：不足 100 台 → 700+ 台（3D 打印 330+ / 尼龙 60+ / 金属 50+ / CNC 250+）
- 品牌：8+（联泰 / Formlabs / 拓竹 / 黑格 / 惠普 / 华曙 / Unicorn / 华曙高科 / 发那科）
- 运行模式：7×24 小时全自动（建立前需凌晨人工盯电话）

**业务边界**：
- 上游：客户下单 → 图纸解析审核 → MES 排程排产
- 本系统：6 服务流水线执行（从图纸到设备上机打印 + 状态回传）
- 下游：各品牌设备厂商 API（不直接与 3D 打印机通信）

**核心业务价值**：
1. 新品牌对接从 1 个月+ 缩短至 1 周（4 倍提速）
2. 7×24 无人值守（建立前凌晨人工盯电话）
3. 设备规模 7 倍增长下系统稳定支撑

## 二、业务流程（三流框架）

> 3D 打印按需制造本质是供应链业务，用信息流/物流/资金流三流框架拆解，本系统核心覆盖信息流 + 物流，资金流由 OMS/财务系统处理，本系统通过订单状态与资金流对接。

### 2.1 信息流（本系统核心覆盖）

```
客户下单 ──► 图纸解析审核（自动+人工）──► MES 排程排产
                                                │
                                    ┌───────────┴───────────┐
                                    │   6 服务流水线（打印阶段） │
                                    │  ① 下载 → ② 解析 → ③ 校验 │
                                    │  ④ 转换 → ⑤ 上机 → ⑥ 上报 │
                                    └───────────┬───────────┘
                                                │
                                    适配器层（按品牌路由）
                                                │
                                    厂商 API 上机 ──► 设备状态实时回传
                                                │
                                    后处理状态回传（质检结果/包装/发货通知）
                                                │
                                    客户可见订单全流程进度
```

**信息流关键节点**：
- 订单→图纸：OMS 下发订单 ID，下载服务获取图纸
- 图纸→切片：解析→校验→转换，生成设备可识别文件
- 切片→上机：适配器匹配品牌，调用厂商 API 下发任务
- 上机→交付：设备状态秒级上报 + 后处理节点状态回传，客户实时可见

**MES 排程策略**（信息流调度核心）：

| 排序维度 | 规则 |
|----------|------|
| 客户重要标签 | VIP 客户优先 |
| 生产优先级 | 内部标注紧急程度 |
| 交期 | 越早越优先 |
| 仓库 | 就近分配 |
| 文件大小 | 大文件优先（大→小） |

### 2.2 物流（本系统覆盖打印 + 后处理）

```
原材料入库
  └──► 打印（6 服务流水线 + 适配器 → 厂商设备执行）
         └──► 静置清洗
                └──► 分拣
                       └──► 打磨 / 后处理
                              └──► 质检
                                     └──► 包装
                                            └──► 发货
                                                   └──► 售后
```

**物流关键特征**：
- 打印阶段：系统全自动调度（设备→任务匹配、状态监控、异常告警）
- 后处理阶段：部分人工介入（打磨/质检），系统跟踪节点状态
- 耗材管理：原材料入库→打印耗料→坏件/废料，与排程排产联动

### 2.3 资金流（OMS/财务系统处理，本系统对接）

```
客户下单付款 ──► 订单确认（OMS）
                     └──► 生产成本核算（耗材 + 设备工时 + 后处理人工）
                            └──► 结算 ──► 账期回款
                                           └──► 售后赔付（合同 SLA / 坏件重打）
```

**本系统与资金流的对接点**：
- 订单状态：打印完成/质检通过/发货 → 触发 OMS 结算节点
- 耗材数据：打印耗料 + 坏件数 → 生产成本核算输入
- SLA 赔付：合同交期违约 → 售后赔付依据

## 四、设计模式

### 4.1 适配器模式 + 策略模式（核心）

**设计目标**：多品牌设备"USB 式热插拔"接入——新增品牌只需实现 IDeviceAdapter 接口，不影响现有流程

```
┌──────────────────────────────────────────┐
│              适配器抽象层                 │
│  ┌────────────────────────────────────┐  │
│  │  IDeviceAdapter (接口)             │  │
│  │  - connect()                       │  │
│  │  - uploadJob(Job)                  │  │
│  │  - getStatus()                     │  │
│  │  - pauseJob()                      │  │
│  │  - resumeJob()                     │  │
│  │  - cancelJob()                     │  │
│  └────────────────────────────────────┘  │
│              ▲                           │
│    ┌─────────┼─────────┐                 │
│    │         │         │                 │
│  ┌─────┐  ┌─────┐  ┌─────┐  ...         │
│  │联泰 │  │惠普 │  │华曙 │               │
│  │适配器│  │适配器│  │适配器│               │
│  └─────┘  └─────┘  └─────┘               │
└──────────────────────────────────────────┘
```

**策略模式**：上机服务根据设备品牌，运行时选择对应适配器策略执行

**适配器模式**：每个品牌适配器封装厂商 API 差异（RESTful / Socket / MQTT / 厂商集群软件），对上层暴露统一接口

**效果**：新品牌对接从 1 个月+ → 1 周，只需实现 IDeviceAdapter + 注册到策略工厂

### 4.2 流水线模式

6 个服务按顺序编排，RabbitMQ 异步解耦：
- 单个服务失败可重试或降级，不影响整体流程
- 每个服务独立部署、独立扩缩容

## 五、技术亮点

### 5.1 "USB 式热插拔"品牌接入

适配器模式 + 策略模式组合，新增品牌零侵入：
- 只需实现 IDeviceAdapter 接口（connect/uploadJob/getStatus/pauseJob/resumeJob/cancelJob）
- 注册到策略工厂，上机服务运行时自动路由
- 新品牌对接从 1 个月+ → 1 周（4 倍提速）

### 5.2 7×24 无人值守

建立前：凌晨人工盯电话，设备异常靠人发现
建立后：设备状态秒级上报（MQTT + WebSocket），异常自动告警，完全无人值守

### 5.3 单集群 → 多集群主动演进

**触发**：富海产区设备集中度突破联泰软件单集群上限

**预判机制**：自建健康度指标体系（设备在线率 / 任务队列长度 / 平均打印时长 / 故障率趋势 / 集群负载均衡度），在瓶颈发生前主动推进重构

**演进结果**：
```
单集群 → 多集群负载均衡
  ├── 集群 A（老厂区）
  ├── 集群 B（富海产区）
  └── 集群 C（备用/扩展）
```

### 5.4 多协议统一适配

8+ 品牌通信方式各异（RESTful API / Socket 自实现 / MQTT / 厂商集群软件 / 主动上报），适配器层统一封装，上层服务无感知

## 六、难点

### 6.1 品牌协议差异大

8+ 品牌的 API 协议、数据格式、通信方式各不相同：
- 联泰：自有集群软件 + RESTful API
- Formlabs：RESTful API
- 部分品牌：无标准协议，需 Socket 自实现
- 部分品牌：设备主动推送状态

**解法**：适配器模式统一封装，IDeviceAdapter 接口屏蔽差异

### 6.2 单集群瓶颈预判

联泰软件单集群有设备数量上限，富海产区设备集中度增长快，等突破上限再改会停线

**解法**：建立健康度指标体系，持续监控集群负载趋势，在瓶颈前主动推进多集群改造

### 6.3 设备规模 7 倍增长下系统稳定

从不足 100 台到 700+ 台，数据量、并发、状态上报频率同步增长

**解法**：
- ShardingJDBC 分库分表应对数据增长
- Redis 缓存热点数据
- RabbitMQ 异步解耦削峰
- Kafka 跨系统数据同步

### 6.4 7×24 高可用

设备不停机，系统不能停

**解法**：微服务独立部署 + RabbitMQ 异步重试 + 异常自动告警 + 多集群容灾

## 九、待办：六角色审阅建议（2026-08-07）

> 阿强（制造企业 CTO）+ 小明（AI 编程同事）+ 老张（Java 后端架构师）对业务框架和业务流程的深入审阅。

### 阿强（CTO）

1. **信息流和物流边界厘清**：6 服务流水线归信息流，物流从"原材料出库→上机打印→出件"起，打印阶段是两流交汇点但别混写。优先级：高
2. **业务定位改"操作系统"叙事**："公司生产运营的核心操作系统，从接单到交付全链路数字化，替代人工调度实现 7×24 无人值守"。优先级：中
3. **物流加在制品（WIP）缓冲概念**：各节点间存在在制品积压，系统跟踪在制品数量和停留时长，证明懂制造不是理想流水线。优先级：高
4. **资金流对接点写具体**：本系统输出打印耗料量、坏件数、设备工时，作为 OMS 成本核算和 SLA 赔付的原始数据输入，不只是"对接状态"。优先级：高

### 小明（AI 同事）

5. **信息流补异常流分支**：校验失败→人工审核/退回、设备故障→任务重调度、质检不合格→返工/报废，系统自动触发异常告警和重调度。优先级：高
6. **加"三流联动"段落**：信息流驱动物流执行，物流状态回传信息流，物流数据输入资金流，资金流约束（SLA/账期）反馈信息流排程决策——不是三条平行线，是互相驱动的闭环。优先级：高
7. **MES 排程补演进路线**：承认当前是规则驱动，补"规划中引入规则引擎和 Agent 智能调度"，与 Agent 排产助手 demo 对齐。优先级：中

### 老张（Java 架构师）

8. **准备 6 服务拆分理由**：解析吃 CPU（STL 解析）、转换吃 IO（切片文件写入），独立扩缩容才有意义，不是为拆而拆。优先级：中
9. **适配器层画在上机服务内部**：不要画成独立层，代码上适配器是上机服务的内部策略，架构图和代码实现要一致。优先级：高
10. **耗材管理提出来单独写**：耗材数据是排程输入（材料够不够决定能不能排）+ 资金流输入（耗料量决定成本）+ 质检关联（耗料异常可能是设备问题）。优先级：中
11. **SLA 赔付补多维**：不只是交期违约，还有质量赔付（航天件全检不合格）、数量赔付（坏件超过合同比例），数据来源：信息流时间戳 + 质检结果 + 坏件数/合同比例。优先级：中
