## 四、面试官不会明说但实际在意的（含 40+ 专项）

1. **"这人 40+ 了，还能写代码吗？"** → "我不只写，我还带团队用 AI 写得更快——lexy 商城就是前端+后端都用 Vibe Coding 交付的。"
2. **"他是来养老的还是来干事的？"** → "养老的人不会下班后写 Agent 训练代码，也不会周末搞金融复盘系统。"
3. **"空降能接住团队吗？"** → "入职 1 个月摸底、半年汰换 50%、1 年建立双周迭代体系——而且我用同样的方法论，组建了 Vibe Coding 团队并交付了生产项目。"
4. **"他说的 Agent 是 demo 还是生产级？"** → 诚实讲清 demo 和生产的差距，但强调"lexy 商城是生产级，Agent 是用同样方法论验证过的，离生产只差工程化补全"。
5. **"他懂制造业还是只是想蹭热点？"** → 真实业务约束（单材料约束、坏件口径、耗料公式不交给 LLM）。
6. **"AI 部分是不是培训班水平？"** → "手写原语→框架编排→团队交付→生产上线，每步都有源码。"
7. **"Vibe Coding 团队是真的还是吹的？"** → "lexy 商城，多语言多货币，已发布生产环境。可以演示。"

## 七、管理三段式（面试核心叙事之二）

这是你证明"我不是只会一种管理模式"的故事线，面试时按这个顺序讲：

```
模式 1：从 0 到 1 建团队（绿信，2016-2018）
  "在绿信，我从 0 开始组建 Java 团队，负责一条产品线，从招聘、搭架构、
   定规范全部自己来，团队从 0 到 30+ 人。这段经历让我掌握了——
   怎么选人、怎么定标准、怎么让新人快速上手。"

模式 2：规模化升级（绿信，2018-2022）
  "产品线跑通后我获得晋升，管理范围扩大到 150+ 人。
   30 人靠人盯就够了，150 人必须靠制度。所以我创建了流程体系——
   不是照搬别人的，是针对当时团队的具体问题（延期、质量、扯皮）设计的。
   这段经历让我掌握了——怎么从'人治'升级到'制度治'。"

模式 3：空降整合（未来工场，2022-至今）
  "到了未来工场，情况完全不同——我不是从 0 开始，而是空降接管。
   团队横跨产品、OMS、Java、测试、大数据、运维六个职能，
   各说各话、互相甩锅。我用了 1 个月摸底，然后推动整合——
   统一流程、明确边界、汰换升级。半年后团队从混乱进入规范，
   1 年后开始起飞。这段经历让我掌握了——怎么在已有团队中做减法、
   怎么处理跨职能冲突、怎么让存量团队焕新。"

为什么三种模式都重要：
  "你现在招的技术负责人，大概率不是去一个空白画布上画——
   要么是团队有了但混乱，要么是团队要扩张，要么是团队要转型。
   三种情况我都经历过，所以我不用'学'，我能直接'做'。"
```

**三种模式的核心差异：**

| 模式 | 场景 | 核心挑战 | 你的解法 |
|------|------|---------|---------|
| 从 0 到 1 | 绿信早期 | 没人、没规范、没架构 | 亲自招聘+搭架构+定规范，30+人团队 |
| 规模化 | 绿信中后期 | 人多了管不过来、流程跟不上 | 创建流程体系，从人治升级到制度治，150+人 |
| 空降整合 | 未来工场 | 跨职能冲突、存量团队惯性、信任缺失 | 摸底→统一→汰换→起飞，跨6职能整合 |

## 九、各经历的写作策略（不是"不写"，是"怎么写"）

### 腾讯/金蝶 — 写，但精炼

**为什么写**：腾讯 T3.2 是中国互联网圈的硬通货，金蝶是 ERP 行业黄埔军校。这两个品牌信号能快速建立信任——"这人是正规军出身"。

**怎么写**：
- 腾讯：2-3 bullet，聚焦"T2.3→T3.2 快速晋级 + 3 次授予股票 + 城市服务 4500 万用户/日均 PV 1200 万"——证明你在顶级平台拿过结果
- 金蝶：1-2 bullet，聚焦"4 年 7 次考核 4A 3B + CRM 项目获集团创新奖"——证明你从职业生涯起点就是 top performer
- 不写：日常业务细节、技术栈细节（10+ 年前的 tech stack 反而暴露年龄）

### 量化交易 — 写，诚实写

**为什么写**：这是兴趣驱动、独立完成的完整项目，体现自驱力和学习能力。面试官喜欢"业余时间还在写代码"的人。

**怎么写**：
- 1-2 bullet，聚焦"用 freqtrade 框架独立完成策略编写、回测、实盘部署"
- 描述策略类型（如：均线交叉、网格交易等），但不展开算法细节
- 诚实标注"兴趣项目，入门级，非专业量化"
- 不写：假装自己是量化专家（面试官如果是业内人士会一眼看穿）

### 前端技术 — 写架构层面

**为什么写**：技术总监需要懂前端架构，不需要写 CSS。你设计的多端架构（Web/Admin/CLI + 双通道认证）是架构能力的体现。

**怎么写**：
- 聚焦架构决策：多端分离设计、双 Axios 实例 + 双通道认证、Vite 构建优化
- 不讲：Vue 3 响应式原理、ECharts 选型细节、CSS 方案
- 面试被追问时坦诚："前端实现层面我有架构判断力，但具体组件开发和样式调整由前端工程师负责"

### 团队制度/流程/人才梯队 — 重点写，这是核心弹药

**为什么写**：这是技术总监岗最重要的证据。面试官要找的不是"会写代码的人"，而是"能让一群人高效写代码的人"。而且你有三种模式的经验——从 0 到 1、规模化、空降整合——这比只经历过一种模式的人强太多。

**怎么写（按两家公司分层）**：
- **绿信（前公司）**：聚焦"从 0 到 1 组建 30+ Java 团队 + 晋升管理 150+ 人 + 创建流程体系"——证明你有从下到上的完整成长
- **未来工场（现公司）**：聚焦"空降 + 跨 6 职能整合（产品/OMS/Java/测试/大数据/运维）+ 混乱→规范→起飞"——证明你能在存量团队中做减法
- 制度建设具体证据：14 方向研发流程、双周迭代（7 工具闭环）、绩效双循环 4 版迭代、项目负责人权责机制
- 每个 bullet 必须有数字（30+ 人、150+ 人、6 职能、14 方向、7 工具、4 版）

### 消费金融 — 压缩到精华

**怎么写**：2-3 bullet，聚焦"从 0 到 1 搭建 Spring Cloud 微服务生态 + 打造 180 人敏捷团队 + 600 亿放款规模"。不写具体业务细节。

### 跨境电商创业 — 一笔带过

**怎么写**：1 行，"独立完成海关报备、通关、ERP 和三单一证报关模块"。创业经历体现全栈和抗压能力，但 1 年太短，不展开。

### retrosys — 面试讲，简历不写

**为什么**：进行中项目，简历上写"进行中"反而显得不专业。面试时作为"我最近在做什么"来讲，体现持续学习。
