## 三、项目质量横向对比 📊

> **方法说明**：从 Bug 标题中提取需求名前缀（` ---` 之前的部分），识别出独立的**项目/大需求**。
> 以下 4 个是 26H1 期间的实际项目；其余如「3D/模型业务」「国内业务」「财务/对账」「询报价/表面处理」「商城/小程序/活动」「后台/系统/权限」等属于系统/业务域归类，不在项目对比维度。
> Bug 按严重程度加权：**1级=250分 / 2级=50分 / 3级=10分 / 4级=1分**。风险分越高 = 质量风险越大。

**项目对比摘要：**

从项目维度看，26H1 质量风险主要集中在 **lexy商城** 和 **战略大客户(宇树)** 两个项目，但两者的问题性质不同。

- **lexy商城**：Bug 数最高（123）、人均最高（41）、4级 Bug 占比最高（36.6%），同时超24H率达到 18%。该项目属于新系统建设期，问题主要集中在后台 Admin、商品/SPU、用户会员、订单等基础模块，Bug 以 UI 打磨、字段回显、交互边界和基础功能完善为主。整体表现为“量大、偏轻、建设期集中暴露”，不宜简单等同于长期质量滑坡。
  - lexy商城的时效问题：产品模块要重构，产品模块相关 Bug 全部推迟解决，所以时效偏慢不完全代表响应慢。
- **战略大客户(宇树)**：Bug 数 86，虽然总量低于 lexy商城，但高危率最高（3.5%）、加权均分最高（10.0），说明 Bug 严重度更高。问题集中在专属折扣、价格计算、包邮规则、客户配置等复杂业务规则，属于“量中等、Bug 更重、业务风险更高”的项目，应作为后续复杂规则类项目的重点复盘对象。
- **合并发货**：Bug 数 45，零高危，超24H率仅 2%，加权均分 9.0，整体质量较稳定。该项目涉及 MES、OMS、前端多组协作，但风险控制较好，可作为跨组协作类项目的正面案例。
- **国际欧洲站**：Bug 数 63，参与人数最多（10人），人均 Bug 最低（6），超24H率仅 2%，风险分最低（28）。该项目属于一次性收尾交付，问题分散在人群和模块中，整体质量风险可控。

综合判断：**lexy商城的问题重点在“新系统建设期 Bug 集中释放与产品模块重构导致时效延迟”，战略大客户(宇树)的问题重点在“复杂业务规则导致高危 Bug 风险”，合并发货和国际欧洲站整体可控。** 后续复盘应避免只按 Bug 数排序，而应结合高危率、加权均分、4级占比、超24H率和项目阶段综合判断。

## 九、组长质量KPI评分体系

> **章节摘要**：本章节建立基于 Bug 加权密度的组长质量 KPI 评分模型。当前已整理前端组、OMS组评分明细；Java组与 lexy商城 拆分口径、MES组开发指标数据仍待补充确认。通过量化 Bug 严重程度权重、剔除迭代日后的有效工作日，计算团队人均日均密度，并以此为基准进行绩效评分，为组长管理提供数据支撑。

### 9.1 计算公式说明

**1. Bug 加权得分**

```
Bug 加权得分 = Σ(Bug数量 × 严重度权重)
```

| 严重度 | 权重 |
|:------:|:----:|
| 1级（致命） | 250 |
| 2级（严重） | 50 |
| 3级（一般） | 10 |
| 4级（建议） | 1 |

**2. 有效工作日**

```
有效工作日 = 本月工作日 - 迭代日（每2周1天）
```

迭代日基于最新迭代日 **2026-06-17** 倒推，每14天1个迭代日。

**3. 个人日均密度**

```
个人日均密度 = 个人 Bug 加权得分 / 有效工作日
```

**4. 团队人均日均密度**

```
团队人均日均密度 = 团队 Bug 加权总分 / 有效工作日 / 活跃人数
```

> 活跃人数：当月有 Bug 数据的成员数

**5. 团队绩效得分**

```
团队绩效 = 取整(75 + (8.2 - 团队人均日均密度) × 5)
```

| 得分范围 | 说明 |
|:--------:|------|
| > 75 | 🟢 加分（密度低于基准 8.2） |
| = 75 | ⚪ 持平（密度等于基准 8.2） |
| < 75 | 🔴 扣分（密度高于基准 8.2） |

**6. 个人状态**

```
个人状态 = 🟢 加分（密度 < 8.2） / 🔴 扣分（密度 > 8.2） / ⚪ 持平（密度 = 8.2）
```

> **章节摘要**：本附录为前端组（陈美琴、黄暖钦、叶建奇）建立基于 Bug 加权密度的组长质量 KPI 评分模型。通过量化 Bug 严重程度权重、剔除迭代日后的有效工作日，计算团队人均日均密度，并以此为基准进行绩效评分。旨在客观衡量前端组月度质量表现，识别异常月份，为组长管理提供数据支撑。

### C.1 计算公式说明

**1. Bug 加权得分**

```
Bug 加权得分 = Σ(Bug数量 × 严重度权重)
```

| 严重度 | 权重 |
|:------:|:----:|
| 1级（致命） | 250 |
| 2级（严重） | 50 |
| 3级（一般） | 10 |
| 4级（建议） | 1 |

**2. 有效工作日**

```
有效工作日 = 本月工作日 - 迭代日（每2周1天）
```

迭代日基于最新迭代日 **2026-06-17** 倒推，每14天1个迭代日。

**3. 个人日均密度**

```
个人日均密度 = 个人 Bug 加权得分 / 有效工作日
```

**4. 团队人均日均密度**

```
团队人均日均密度 = 团队 Bug 加权总分 / 有效工作日 / 活跃人数
```

> 活跃人数：当月有 Bug 数据的成员数（如 2026-05 陈美琴无 Bug，活跃人数=2）

**5. 团队绩效得分**

```
团队绩效 = 取整(75 + (8.2 - 团队人均日均密度) × 5)
```

| 得分范围 | 说明 |
|:--------:|------|
| > 75 | 🟢 加分（密度低于基准 8.2） |
| = 75 | ⚪ 持平（密度等于基准 8.2） |
| < 75 | 🔴 扣分（密度高于基准 8.2） |

**6. 个人状态**

```
个人状态 = 🟢 加分（密度 < 8.2） / 🔴 扣分（密度 > 8.2） / ⚪ 持平（密度 = 8.2）
```
