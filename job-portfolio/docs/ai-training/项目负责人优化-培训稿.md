## 开场引入（3 分钟）

### 三个痛点

- **有责无权**：名为负责人，实际没有调动资源的权力
- **有权无责**：负责人在关键时刻缺席，出了问题无人兜底
- **流程断层**：需求到上线的各阶段之间缺少衔接，信息不同步

### 本次解决三个问题

**谁来当、干什么、怎么奖罚。**

---

## 一、权责相匹（5 分钟）

### 核心理念

> 干得多、管得宽 → 有激励；出了问题、延期了 → 有责任。

### 奖励

| 需求类型 | 判定标准 | 奖励 |
|---------|---------|------|
| 复杂需求 | 1 人周以上 | **2 分** |
| 中等需求 | 2 人天以上 | **1 分** |
| 简单需求 | ≤2 人天 | — |

- 以**完成**为标准，积分与绩效挂钩。

### 惩罚

**提测阶段延期扣分（/天）**

| 需求类型 | 扣分 |
|---------|------|
| 复杂 | **0.5** |
| 中等 | **0.3** |
| 简单 | **0.1** |

**上线阶段延期扣分（/天）**

| 需求类型 | 扣分 |
|---------|------|
| 复杂 | **1.5** |
| 中等 | **0.8** |
| 简单 | **0.2** |

### 设计逻辑：前期轻、后期重

- 提测延期 → 影响测试排期 → 扣分较轻
- 上线延期 → 影响业务承诺 → 扣分较重（复杂需求上线扣分是提测的 **3 倍**）
- 目的：倒逼主负责人在前期就把控节奏

### 一页纸总结

```
┌──────────────────────────────────────────┐
│  奖励：复杂 2 分 / 中等 1 分              │
│  惩罚：提测轻（0.5/0.3/0.1）              │
│         上线重（1.5/0.8/0.2）             │
│  原则：前期轻、后期重，倒逼节奏把控         │
└──────────────────────────────────────────┘
```

## 二、需求评审与开发反讲（8 分钟）

### 2.1 确定主负责人

**唯一标准：主流程关键路径所在组**

| 项目类型 | 建议人选 | 原因 |
|---------|---------|------|
| 紧急 | **熟手** | 无试错时间，快速判断风险 |
| 非紧急 | **轮流坐庄** | 培养梯队 |

- **t+1 天**必须确定，同步确定反讲时间。

### 2.2 开发反讲

> **1 人周以上的项目，必须有开发反讲。**

**两大内容**：

| 内容 | 目标 |
|------|------|
| 分组负责人讲本组主流程设计 | 全局技术架构对齐 |
| 需求细节理解（开发逻辑 vs 产品功能） | 消除理解偏差 |

**工作分解三要素**：任务分解、工时评估、各组联调时间约定。

### 一页纸总结

```
┌──────────────────────────────────────────┐
│  需求评审 → t+1 确定主负责人               │
│           → 同步确定反讲时间               │
│                                          │
│  反讲（1人周+必须做）                      │
│  ├─ 讲本组设计（全局对齐）                 │
│  └─ 需求理解对齐（消除偏差）               │
│                                          │
│  输出：任务分解 + 工时评估 + 联调时间       │
└──────────────────────────────────────────┘
```

## 三、开发阶段（8 分钟）

### 3.1 进度会议

| 维度 | 要求 |
|------|------|
| 频次 | 每周 **2 次**（周三、周五） |
| 节奏 | 周三摸底 → 周四推动 → 周五对表 |

**三段式**：

| 阶段 | 动作 | 产出 |
|------|------|------|
| 会前 | 督促更新禅道状态 | 最新进度数据 |
| 会中 | 看板 + 燃尽图 + 问题清单 | 偏差识别 + 风险暴露 |
| 会后 | 主负责人亲自推动解决 | 问题闭环 |

### 3.2 关注联调时间

- 联调是项目**最容易失控**的环节
- **核心手段** —— "揪着各组负责人"
  - 提前确定联调里程碑
  - 提前暴露接口依赖
  - 主动追问、持续跟进

### 3.3 关注测试用例评审

- **评审时间**：确保测试团队有足够时间准备
- **评审质量**：用例太浅 → 漏测 → 上线后出问题

### 一页纸总结

```
┌──────────────────────────────────────────┐
│  进度会议：每周 2 次（周三摸底、周五对表）  │
│  ├─ 会前：督促状态翻转                     │
│  ├─ 会中：看板 + 燃尽图 + 问题清单         │
│  └─ 会后：协调解决问题                     │
│                                          │
│  联调：揪着各组负责人，提前定里程碑         │
│  用例：关注评审时间和质量                   │
└──────────────────────────────────────────┘
```

## 四、测试与上线（10 分钟）

### 4.1 测试阶段

**提测 —— 统一**

- 统一测试时间
- 统一测试版本和内容

**反面案例**：A 组提测了，B 组还没提测，测试拿到不完整版本，测了半天白测。

**测试质量 —— 两个抓手**：

| 抓手 | 目标 |
|------|------|
| BUG 翻转速度 | **日清日结**：今天发现今天修完验证完 |
| 协助测试 | 环境、数据、边界场景问题，协调开发支持 |

### 4.2 上线发布

**四要素**：

| 要素 | 要求 |
|------|------|
| 统一发布时间 | 全项目一个窗口发布 |
| 发布内容/功能 | 明确本次所有内容 |
| 发布顺序 | 系统间、模块间有依赖，顺序错 = 故障 |
| double check | 发布前最后确认 |

**发布顺序示例**：

```
错误：前端发布 → 用户看到新界面 → 后端未发 → 接口不通 → 功能不可用
正确：后端发布 → 接口验证 → 前端发布 → 用户看到完整功能
```

**发布后**：各组观察系统运行状况，上线后第一个小时、第一天、第一周都是高风险期。

### 一页纸总结

```
┌──────────────────────────────────────────┐
│  测试阶段                                 │
│  ├─ 提测：统一时间、统一版本              │
│  ├─ BUG：日清日结                        │
│  └─ 协助：解决测试阻塞问题                │
│                                          │
│  上线阶段                                 │
│  ├─ 统一发布时间                          │
│  ├─ 安排发布顺序（先依赖、后被依赖）       │
│  ├─ double check 发布内容                 │
│  └─ 发布后观察 30 分钟+                   │
└──────────────────────────────────────────┘
```

## 五、分组负责人（3 分钟）

### 角色定位

| 角色 | 维度 | 职责 |
|------|------|------|
| **主负责人** | 项目维度 | 全流程管理 |
| **分组负责人** | 组维度 | 本组具体执行 |

**分组负责人是主负责人的"手脚"**。主负责人不可能深入每个组的代码，必须依赖分组负责人传递压力、收集信息、推动执行。

### 职责对照

| 阶段 | 分组负责人职责 |
|------|--------------|
| 开发反讲 | 组织本组任务分解、工时评估、模块设计 |
| 开发阶段 | 关注联调里程碑时间 |
| 测试阶段 | 关注提测时间、BUG 修复及时性 |
| 上线发布 | 组织本组发布、double check 本组内容 |

## 总结（3 分钟）

### 八句口诀

| 序号 | 口诀 | 含义 |
|------|------|------|
| 1 | **权责相匹** | 干得多有激励，延期了有责任，前期轻、后期重 |
| 2 | **关键路径** | 主负责人看关键路径，紧急用熟手、非紧急轮流 |
| 3 | **反讲必做** | 1 人周以上必须有反讲，对齐"怎么做" |
| 4 | **每周两回** | 周三摸底、周五对表，会前→会中→会后三段式 |
| 5 | **揪着不放** | 联调时间要"揪着各组负责人"推动 |
| 6 | **统一为要** | 统一提测、统一发布、统一顺序 |
| 7 | **double check** | 发布前最后确认，发布后持续观察 |
| 8 | **手脚并用** | 分组负责人是主负责人的执行抓手 |
