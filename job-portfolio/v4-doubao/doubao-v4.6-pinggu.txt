# 简历评估：苏坚生 — 中等公司AI负责人岗

## 核心判断

**工程管理底子扎实，但AI深度偏浅、成果偏"样板间"，与30-50人团队的AI转型需求存在结构性错配风险。** 可以面试，但必须带着尖锐问题去验证，不能被"20年研发+10年管理+AI落地"的组合拳直接说服。

---

## 一、值得肯定的地方（务实面）

| 维度 | 具体表现 | 对中等公司的价值 |
|------|---------|----------------|
| 履历完整度 | 腾讯→金蝶→消费金融→制造→跨境，行业跨度大 | 跨行业迁移能力强，能快速理解新业务 |
| 管理经验 | 三种建队情形（从0/扩张/空降整合）都走过 | AI转型必然涉及组织变革，这类经验稀缺 |
| 工程化底色 | 金融等保三级、700+设备7×24、微服务生态 | AI系统最终要上生产，工程化能力是底座 |
| 行动意愿 | "自己先把全链路跑通再推团队" | 比纯PPT型AI负责人强，至少肯下场 |
| 自我认知 | 主动标注"GMV起步期""尚未规模化铺开" | 没有把验证项目吹成商业奇迹，诚实度尚可 |

## 二、必须追问的疑点（批判面）

### 1. AI成果的"含金量"需要拆解

简历中真正的AI项目只有两个，且都存在问题：

**lexy商城（3周交付）**
- "传统估算约6周"——这个估算是谁给的？基线团队多大？如果传统团队是5人估6周，而AI项目是总监亲自下场+小团队突击，对比口径不公平。
- 3周里含1周需求与框架，实际开发仅2周。一个多语言多货币的跨境电商商城2周交付，**代码质量、可维护性、后续迭代成本**如何？快不一定是好事，可能是技术债。
- "测试工作量降一半以上"——没有绝对数据，降一半是从多少到多少？AI自动化验收的漏测率如何？
- 商业结果："GMV起步期，不夸大"=**实际上没有可量化的商业成果**。3周抢出的市场窗口，后续订单量、留存、复购都没提。

**Agent排产助手（4周验证）**
- 明确写了"工程化验证阶段，尚未规模化铺开"——等于**没落地**。
- "4周系统训练走完Agent全链路"——这更像是个人技术学习项目，不是团队能力建设。LangGraph、Supervisor、Token Exchange都是2024-2025年的热门技术栈，4周速成，深度存疑。
- 排产6环节只提了"合同环节用RAG"，其他5环节AI做了什么？规则引擎算的部分本来就不需要AI。

### 2. "自研LLMOps网关token-hub"——听起来专业，实际呢？

这是简历中最像"AI基础设施"的东西，但信息极度模糊：
- 日调用量多少？峰值QPS？
- 接了几个模型？实际在生产中跑了哪些业务？
- 降级策略触发过几次？效果如何？
- 是个人项目还是团队在维护？
- **如果只是个Demo级别的路由网关，那"LLMOps"这个词就是包装。**

### 3. 管理规模与目标团队的错配

候选人管过150+团队，现在目标是30-50人。这带来三个风险：

- **管理过重**：150人团队需要的双周迭代、7工具闭环、绩效数据链路、项目负责人机制，搬到30-50人团队可能变成流程负担。小团队需要的是扁平、快速、一把手亲自冲。
- **亲力亲为的悖论**：简历写"亲手写了lexy-admin全栈"，作为研发总监亲自写全栈，要么是团队太小没人可用，要么是授权不足。到了30-50人的公司，AI负责人应该是搭体系、定方向、拿资源，而不是自己写CRUD。
- **薪资预期**：深圳+研发总监+20年经验，薪资包大概率在80-120万区间。30-50人的中等公司能否承受？如果给不起，候选人可能把这里当跳板。

### 4. AI技术栈的"厚度"问题

```
Go / Java / Python / LangGraph / Spring Cloud / token-hub / MCP Server / RBAC / RAG / StateGraph
```

- LangGraph、MCP、StateGraph都是2024年以后才流行的概念，候选人2022年就入职未来工场了，**前两年在做什么？** AI转型是近两年才开始的，实际AI经验可能只有1-2年。
- 没有提到：模型微调（LoRA/SFT）、向量数据库选型与调优、Prompt工程的体系化方法、AI系统的成本优化（这对中等公司极其重要）、数据飞轮建设。
- RAG只提了"合同环节用RAG检索条款"，没有说明检索准确率、召回率、chunk策略、评估方法。

### 5. 职业稳定性与动机

- 博时达供应链只做了1年（标注为项目制，可接受）。
- 未来工场从2022.04至今，4年多，稳定。
- 但简历版本号"v4.6"说明在频繁修改，可能正在积极看机会。**为什么要从研发总监岗跳出来找AI负责人？** 是公司AI投入不足？还是和管理层有分歧？还是自己想转型？这个动机必须问清楚。

## 三、面试必问题单（验证用）

### 技术深度验证
1. token-hub网关：现在日调用量多少？接了哪几个模型？最近一次降级是什么场景？怎么处理的？
2. lexy商城：2周开发出来的代码，现在谁在维护？过去3个月改了多少bug？技术债清单有多长？
3. Agent排产：6个环节里，哪些是AI真正在做决策，哪些只是规则引擎套了个Agent壳？工具F1分数具体是多少？
4. 如果让你给我们公司（30-50人）做AI基础设施，第一阶段你会买什么、自建什么、预算怎么分？

### 业务价值验证
5. lexy商城上线2个月了，俄罗斯市场的订单量、客单价、退货率分别是多少？AI在其中贡献了什么？
6. 你说"测试工作量降一半"，那漏测率呢？上线后线上bug数和传统项目比是升了还是降了？
7. 6场AI培训覆盖200+人，培训后有多少人真正在工作中用AI？有没有跟踪数据？

### 管理适配验证
8. 你管过150人团队，现在管30-50人，管理方式会做哪些调整？哪些流程你会砍掉？
9. 如果业务部门（比如销售、客服）不愿意用AI，你怎么推动？
10. 中等公司预算有限，大模型API成本可能是笔不小的开销，你怎么控制成本？有没有实际的成本优化案例？

### 动机验证
11. 你在未来工场已经是研发总监了，为什么要出来找AI负责人的机会？
12. 你期望的薪资范围是多少？如果公司给不到你之前的级别，你能接受吗？

## 四、录用决策建议

| 场景 | 建议 |
|------|------|
| 公司有钱、有明确AI战略、需要有人搭体系带团队 | **可以考虑**，但要求候选人给出90天落地计划，且前3个月必须有可量化的产出 |
| 公司还在摸索AI方向，需要一个人来"探索+证明价值" | **谨慎**，候选人更擅长工程化和规模化，不擅长从0到1的探索期。探索期需要的是敢试错、能快速迭代的人，不是流程体系型管理者 |
| 公司预算有限，希望AI负责人既能写代码又能带团队 | **不匹配**，候选人薪资预期高，且亲自写代码的意愿和能力需要验证（近10年主要做管理） |
| 公司AI转型阻力大，需要有人推动组织变革 | **可以考虑**，候选人的空降整合经验（未来工场6职能团队）正是这类场景需要的 |

---

## 五、总结

这份简历的**包装水平高于实际AI成果**。候选人的核心竞争力是"工程化+管理"，AI是近两年才加上的标签，且成果多为验证级、样板级，没有规模化的商业成功案例。

对于30-50人的中等公司，AI转型最需要的不是一个"管过150人的研发总监"，而是一个**能在有限资源下快速验证AI价值、说服老板持续投入、让业务部门真正用起来**的人。候选人的工程化能力是加分项，但管理风格和AI深度都需要在面试中严格验证。

**建议：面试，但不要急着发offer。至少安排2轮技术深度面+1轮业务场景模拟，重点验证"AI成果的真实性"和"小团队管理的适配性"。** 如果面试中发现token-hub、lexy商城、Agent排产这三个项目有明显注水，直接pass。
