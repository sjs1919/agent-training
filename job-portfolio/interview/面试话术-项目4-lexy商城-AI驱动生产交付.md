## 二、AI 驱动全流程生产交付

> 这是项目 4 的核心卖点——**不是"AI 写了几段代码"，是"从设计到上线整个交付链路都是 AI 驱动的生产流程"**。

### 前端：Figma → 大模型微调 → 界面交付

```
Figma 设计稿
   → 大模型微调（理解设计规范/组件库/视觉语言）
   → 界面交付（AI 生成页面，人工验收）
```

### 后端 + Admin：用户故事 → 规格 → 计划 → TDD 测试先行 → AI 编码 → 自动化验收 → 人工轻量验收 → 上线

```
用户故事 → 规格说明（spec）→ 实现计划（plan）
   → 【TDD 测试先行】先写测试/验收条件，测试=可执行的规格
   → AI 编码（目标：让测试通过）
   → AI 自动化验收（同一套测试自动验证，按验收条件验收）
   → 人工简单功能测试 + 验收（轻量）
   → 上线部署
```

**关键**：TDD 让 AI 编码被测试**从源头约束**——测试先写好，AI 不是"写完再验"而是"按测试写"，质量从源头卡住。这套测试**一测两用**：既驱动 AI 编码，又做自动化验收，这是测试强度比传统轻 50% 以上的根基。这不是"三道人工闸门"，是"测试驱动 + 自动化验收为主、人工轻量兜底"。

### 我的角色（技术主导 + 亲手实现）

**全程参与**：从需求调研 → 组织用户故事 → 构建整个前后端框架 → 联调交互 → 参与 admin 端全栈实现。

**主导选型与设计**：
- 主导**工具 / 模型 / 套餐的选型**
- 参与**前端交互框架、后端架构设计**
- 构建**三端交互**（lexy-admin 后台 / lexy-web 消费端 / 前端）
- **敏感信息保护**设计
- **门禁设计**（AI 代码验收防线）
- 参与**全自动化测试验收策略**

> 定位：既能主导（选型/架构/门禁/测试策略），又能亲手写（admin 全栈实现）。这是"资深个体户"和"组织能力者"之外的第三种——**技术管理者亲自下场**。
>
> **团队视角**：这不是一个人 + AI 干的，是**带团队用这套方法交付**——我定规格、门禁、验收策略，团队按规格驱动 + TDD + 自动化验收协作，AI 是产能放大器。我全程参与，但不替代团队。

## 三、工程化方法（AI 协作的防线）

> 面试官问"你团队用 AI 做了什么"时，从这里取——**讲方法论，不讲工具**。

- **规格驱动**：每个需求先写用户故事 → 规格说明 → 实现计划，AI 在已决策的边界内执行，不漫游
- **TDD 测试先行**：先写测试/验收条件（测试 = 可执行的规格），再让 AI 编码，目标就是让测试通过
- **AI 自动化验收为主（质量主力）**：
  - **AI 单测**（单元测试）
  - **集成测试**
  - **全流程自动化测试**（按验收条件自动化验收）
  - AI 生成代码后按验收条件自动化验收，不合格不提交——**这是质量主力**
- **人工只做轻量验收**：AI 自动化验收通过后，人工测试只做**简单的功能测试和验收**，即可上线
- **测试强度对比**：比传统开发轻 **50% 以上**——传统靠人海测试，这里靠 TDD + 自动化验收
- **上线部署**：验收通过才部署生产

> 与项目 3 的 AI 转型期呼应：这就是"workspace 团队提示词 + AI 代码门禁 + 用结果说话"的落地实例。
