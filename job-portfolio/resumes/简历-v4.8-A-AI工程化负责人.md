- **技术方案**：
  - **Agent 编排**：LangGraph StateGraph 做状态机编排，Supervisor 模式协调多 Agent 分工
  - **RAG 检索增强（向量库选型与工程化 · 专项）**：企业内部知识库场景，选型评估五维度——①私有化部署（合同/履约数据不出公司）②中文检索效果③混合检索能力（合同编号/物料编码需精确匹配 + 条款语义召回）④运维复杂度⑤与 Java/Python 技术栈兼容；最终选型 **Milvus**（开源分布式向量库，HNSW 索引，私有化部署，搭配 bge-large-zh 中文 embedding 模型）；检索层采用 **BM25 关键词 + 向量语义混合检索 + RRF 融合排序**，兼顾精确匹配与语义召回；工程化落地：文档按语义段落切片（200–500 字，重叠 50 字），元数据过滤（合同类型 / 客户 / 时间范围），Top-K 检索后 Cross-Encoder 重排序提升准确率
  - **规则引擎**：单材料约束、坏件口径、耗料公式等真实业务规则由规则引擎计算，确保业务逻辑准确
  - **评估闭环**：自研评估指标（工具 F1 / 完整性 / 订单命中），量化 Agent 效果
  - **治理体系**：配套权限（RBAC）+ 审计 + 护栏，保障 Agent 行为可控可追溯
- **经营结果**：排产 6 环节智能改造方案已在产线试运行，支撑核心排产环节
- **商业价值**：排产从经验驱动转为数据 + AI 辅助，方向是用多 Agent 协作替代部分人工排产、缩短交付周期（注：当前为工程化验证阶段，尚未规模化铺开，如实标注）
