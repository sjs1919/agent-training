## 核心实践

### 故事一：从 0 组建 AI 编程团队，交付生产级产品

**背景**：2025 年我意识到 AI 编程不只是个人效率工具，而是可以改变团队协作方式的工程范式。但大多数团队还停留在"用 Copilot 补全代码"的阶段，没人知道怎么用 AI 做团队级交付。

**我的做法**：

1. **先个人验证**：用 Vibe Coding 方法论（规格驱动 spec→plan→task 三件套 + Claude/Trae/CodeGraph 多工具分工 + 四防线验收），独立交付了 3 个全栈项目——多租户 LLM API 网关(Go，密钥池加权+熔断自愈+SSE 双协议+计费)、A股复盘系统(Vue3+FastAPI，需求工程化+CI 安全门禁)、规格驱动文档体系。证明了方法论可行

2. **再建团队**：组建前端+Java 后端小团队，用同样方法论交付 lexy 多语言多货币商城。关键是建立了团队 AI 协作工程规范——不是"每个人用自己喜欢的 AI 工具"，而是统一规格格式、统一工具分工、统一验收标准

3. **能力建设**：组织 2 场 AI 编程培训覆盖 10+ 人次（Prompt 工程+AI 编程实战），规划 Agent 能力建设路线图，推动团队从"会用 AI 工具"升级为"工程化约束 AI 协作"

**结果**：验证了 AI 协作从个人到团队的规模化路径。团队用 AI 协作的交付速度和质量，显著高于传统开发模式。

**教训**：AI 编程的瓶颈不是工具，是管理——怎么拆分任务让 AI 能独立完成、怎么验收 AI 的产出、怎么让团队成员信任 AI 而不是绕过它。这些是管理问题，不是技术问题。

### 故事二：用 Agent 技术验证制造业智能调度的可行性

**背景**：未来工场有 700+ 台 3D 打印/CNC 设备，排程排产是核心瓶颈。订单交期紧、材料约束多、设备负载不均衡，传统规则引擎覆盖不了所有边界情况。我想验证 Agent 能否用 LLM 的推理能力来处理这些复杂的调度决策。

**我的做法**：

1. **系统补齐 Agent 技术栈**：坦白说，2026 年初我还没做过 Agent 开发。我用 4 周做了系统训练——手写 ReAct 循环（理解 Agent 原语）→ LangGraph StateGraph 编排（框架化）→ Supervisor 多 Agent 协作（多智能体）→ Token Exchange 鉴权（安全）→ RAGAS 评估（质量闭环）。源码可追溯至 `agent-training/scripts/`

2. **锁定制造业载体**：demo 始终以 3D 打印/CNC 排程排产为载体，不跨行业。订单查询/库存检查/设备负载/客户信用/合同延期——用真实业务数据，覆盖真实业务约束（单材料约束、坏件口径、耗料公式不交 LLM 让模型自己算）

3. **输出 6 环节智能改造方案**：订单评审→物料需求→产能评估→进度跟踪→合同管理→调度决策。每个环节标注了当前人工怎么做、Agent 可以替代什么、必须保留什么

**结果**：端到端验证了 Agent 在制造业场景的可行性，输出了可落地的技术方案。混合检索(BM25+RRF+Cross-Encoder)把目标合同从 top3 提到 top1，RAGAS 4 指标量化评估检索质量。

**教训**：Agent 的瓶颈不是模型，是业务规则。合同延期 0.5%/日赔付、航天件全检+报废、加急绿色通道——这些规则必须内嵌到 Prompt 和工具里，模型不知道。另外，Token Exchange 权限收缩链 + Trace ID 全链路审计是 Agent 系统区别于普通后端的安全新课题，多数团队没想过。

### 故事三：空降 150 人跨职能团队的整合与体系搭建

**背景**：2022 年加入未来工场时，产品/OMS/Java/测试/大数据/运维 6 个职能团队各自为战，没有统一流程，没有绩效考核，质量问题频发。

**我的做法**：

1. **摸底期（1 个月）**：不急于动手，先理解业务、盘点人员、识别关键问题。发现最大的问题是"没人知道好坏标准"——没有质量基线、没有交付标准、没有绩效体系

2. **汰换期（半年）**：按摸底结果调整人员结构，从 0 到 10 搭建智能团队

3. **起飞期（1 年+）**：搭建三根支柱——
   - **绩效体系**：设计数据驱动考核（交付 60%+质量 20%+技术沉淀 15%+其他 5%），17 个月 4 版迭代（L1 规则→L2 机制→L3 文化），团队质量基线内化，分数区分度稳定在 70-80 分
   - **研发流程**：从 0 到 1 搭建 14 方向流程体系，双周迭代 7 工具闭环，产品/研发/测试错位 1 周三岗流水线
   - **智能机器系统**：设备从不足 100 台扩展至 700+，7+ 品牌 API 统一适配，6 服务流水线 + 策略模式/适配器模式，新品牌接入 1 月→1 周

**结果**：团队从混乱到规范到起飞。绩效体系运行 17 个月，质量指标从"多数人不及格"到"多数人满分"。智能机器系统 7×24 稳定运行。

**教训**：空降管理者最容易犯的错是"上来就改"。我的经验是"先摸底，再动刀"——第一个月什么都不改，只听、只看、只问。等团队信任你、你理解业务后，再动手，成功率翻倍。
