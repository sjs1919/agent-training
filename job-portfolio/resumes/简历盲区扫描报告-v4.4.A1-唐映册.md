# 苏坚生简历 v4.4.A1 盲区扫描与改进报告（唐映册）

> 范围：对照 7 个目标 JD 的共性能力要求，诊断 v4.4.A1 的盲区、结构问题、可执行改动，并给出双定位判断。所有建议均基于简历已有事实，**不虚构任何数据**；涉及"补一句"的均标注"需候选人确认/回填"，避免硬编。

## 一、盲区扫描

### 1.1 共性能力覆盖矩阵

| # | 能力点（JD 高频） | 简历覆盖 | 对应 JD | 分类 | 说明 |
|---|---|---|---|---|---|
| 1 | AI coding / 工程化落地 | **强** | JD1/2/3/7 | 优势 | lexy 3 周 2 倍提速、Vibe Coding、TDD+AI 验收；差异化主轴，最稳 |
| 2 | 多 Agent 编排 / 全链路 | 中（技术有·规模无） | JD1/3/4 | 可解释弱项（规模） | ReAct→LangGraph→Supervisor→鉴权→评估闭环都覆盖，但标"非规模化生产" |
| 3 | LLM API 网关 / 调度 / 鉴权 | **强** | JD3/6/7 | 优势 | token-hub（Go）+ Java MCP Server，自带可运行代码，硬证据 |
| 4 | 0→1 闭环 / 躬身入局 | **强** | JD2/3/all | 优势 | 三次 0→1、lexy 亲手写全栈 |
| 5 | 跨职能管理 20–150 人 | **强（超配）** | all | 优势 | 150+ / 6 职能 / 30+，甚至超 P8（20 人）要求 |
| 6 | RAG / Memory | 弱 / 缺 | JD3/4 | 可解释弱项 → JD3 偏致命 | 全文未出现；JD3 硬要求 |

| 8 | 百万级 Agent 并发 | 弱（AI 层无） | JD1/7 | 致命盲区（JD1） | 传统高并发有（腾讯 1200 万 PV/日、绿信 600 亿），但 AI/Agent 层无规模证据 |
| 9 | 模型微调 LoRA/P-Tuning/vLLM | 缺 | JD6 | 致命盲区（JD6） | JD6 硬门槛（70–100k·15 薪）；其余 JD 多不要求 |
| 10 | 多模态 / NLP | 弱 / 缺 | JD4 | 可解释弱项 → JD4 部分致命 | 已知弱项；多数目标岗"非算法研究"可兜 |

### 1.2 候选人的"隐藏盲区"（JD 没写、但负责人岗会看）
- **AI 业务价值未量化**：lexy 写"零星用户访问与订单"——AI 只证明了"交付提速"，没证明"带来业务结果"。负责人岗要的是 AI→营收/效率/成本的可量化闭环。
- **"生产级"与"非规模化"自相矛盾**：一句话 Pitch 写"生产级交付"，细节写"非规模化生产"，读者一眼抓到不一致 → 可信度打折。
- **一号位主动语态不足**："鼓励不强推"在 JD2（AI 一号位 / 汇报 CTO）语境下偏弱，JD2 要的是"我定战略、推全员"。
- **AI 成本 / ROI 未呈现**：token-hub 有计费能力，但没说成本优化 / 模型 ROI。
- **AI 数据合规未呈现**：只有传统等保三级，AI 数据治理 / 合规未显性化。

### 1.3 分 JD 匹配速览
- **JD1（AI 应用负责人 / 百万 Agent / 70–100k）**：强在 coding+网关；**致命缺口 = 百万并发 + VS Code 插件**；Agent 规模不够。→ 投前需补"规划中 / 可迁移"口径。
- **JD2（AI 总监 / 一号位 / 50–80k）**：强在 0→1 + 躬身 + 管理；弱在"鼓励不强推"语态、AI 战略一号位感。→ 改主动语态可投。
- **JD3（Agent 平台 / 40–50k）**：强在编排全链路 + 网关 + 架构；**缺口 = RAG/Memory**。→ 补 RAG/Memory 一句可投。
- **JD4（AI Agent 负责人 / 40–70k）**：强在集成 / 编排；缺口 = 多模态 / NLP + 规模化部署。→ 多模态是硬伤，需判断是否投。
- **JD5（港华能源 / 3–5 万）**：高度匹配（Agent 架构 + 工具调用 + 业务集成 + 内部推广 + 迭代闭环），几乎全覆盖。→ 最稳的一档。
- **JD6（AI 技术总监 / 微调 / 70–100k·15 薪）**：强在管理 50 人 + Java + Agent；**致命缺口 = LoRA/P-Tuning/vLLM 微调**。→ 硬门槛，建议慎投或单开版。
- **JD7（P8 / 20 人+ / SaaS / 高并发）**：强在架构 + 高并发（传统）+ 管理；弱在 AI 层高并发证据。→ 传统高并发可迁移，可投。

**结论**：没有"全军覆没"的盲区。最危险的是 **JD1 的百万并发、JD6 的微调**——这两个是硬门槛型致命盲区，且都集中在高薪档。其余多为"可解释弱项"，靠措辞和面试补即可。

## 二、结构剩余问题

1. **价值三轴轨迹线——部分解决了单薄，但引入新风险**。箭头串证据点让" progression "可见，但每轴压成一行后读起来像"活动流水账"而非"能力定义"。总监简历的三轴应传递"我能做什么（能力深度）"，现在更像"我按时间做了什么"。建议箭头前补半句能力定义。
2. **"非规模化生产"标注——对总监简历是减分**。诚实是好事，但"团队级工程化验证（非规模化生产）"紧挨旗舰 AI Agent 工作，会触发"这人真能当 AI 负责人吗"的怀疑。建议：保留"团队级验证"的诚实，把"非规模化生产"替换为**可核实的部署口径**（如"已在 X 产线试运行 / 支撑 Y 个排产环节 / 日均 Z 次调用"），让事实自己说话；"规模有限"留给面试讲。
3. **Pitch 与细节矛盾未消**。一句话"生产级交付" vs 细节"非规模化生产"——必须统一。建议 Pitch 的"生产级交付"只指向 lexy（确实上线），Agent 排产单独定性，不共享"生产级"一词。
4. **智能机器管理系统 block 偏题**。700+ 设备是"稳团队 / 规模化架构"证据，但与 AI 负责人目标弱相关且占篇幅。建议压缩为 2–3 行的"规模化架构能力"佐证，腾出空间给 AI 深度（RAG / 成本 / 治理）。
5. **lexy "零星用户访问与订单" — 可信度弱点**。直说"零星"拉低 AI 业务价值感。建议改"已上线生产环境（俄罗斯市场），新市场爬坡期"，用定性 + 可核实口径不强调"零星"；若有首月单量就补数字。
6. **一句话 Pitch 主语仍是"研发总监"**。目标岗是 AI 负责人 / 总监，简历应让 AI 成为首要身份。当前框架是"研发总监做 AI 转型"，对 JD1/JD2 的"AI 一号位"期待偏弱。建议在标题 / 价值主张把 AI 身份前置。

## 三、可执行改进建议（P0 / P1 / P2）

### P0（投递前必改，影响是否被约面）
- **P0-1 统一"生产级 / 非规模化"口径**：把一句话 Pitch 的"生产级交付"限定为 lexy 商城（确已上线）；Agent 排产改为"团队级工程化验证 + 可核实部署口径"，删除"非规模化生产"四字。→ 改「一、领导价值主张」与「三、Agent 排产」两段。
- **P0-2 补 RAG/Memory 一句（需候选人确认）**：请候选人确认 Agent 排产 / LangGraph StateGraph 是否承载了 Memory / 状态记忆或知识检索。若用了，补"Agent 状态管理与上下文记忆（Memory）"；若没做 RAG，不编，但在「核心能力①」点出"具备 Agent 上下文管理"以对接 JD3。→ 改「二、核心能力①」与「三、Agent 排产」。
- **P0-3 百万并发诚实标注**：AI 层不编规模。在「绿信 / 腾讯」经历强化传统高并发（600 亿放款、1200 万 PV/日），并加一句"高并发高可用架构经验可迁移至 Agent 服务化"；对 JD1 的百万级 Agent 在简历中标"目标 / 规划中"而非已达成。→ 改「绿信」「腾讯」段 + 目标岗备注。
- **P0-4 微调（JD6）决策**：JD6 的 LoRA/P-Tuning/vLLM 是硬门槛。请候选人决策：投不投 JD6？若投，在「核心能力」补"模型微调与推理加速（规划中 / 学习中）"并准备面试证明路径；若不投，版 B 不列入 JD6。→ 见第四部分双定位。

- **P1-4 "鼓励不强推"改主动语态**：改"以躬身验证建立示范，推动团队规模化采纳 AI 工程化"。面试再讲 influence 实质。改「三、管理主线」。
- **P1-5 token-hub 补成本 / ROI**：若有数据补"模型调用成本可视化 / 降低 X%"；没有则写"建立 token 成本核算机制，支撑模型选型 ROI 评估"。改「三、lexy / AI 基础设施」。

## 四、双定位判断

**判断：一份通投版不够，建议分两个微调版（非重写）。**

理由：目标岗分两簇，盲区画像不同——
- **AI 负责人簇（JD1/2/4/5）**：看重 AI coding 全链、Agent 规模化、战略一号位、跨团队推动。该簇不硬要微调 / 算法（JD1 明说无需微调），但看重规模与主动语态。
- **技术总监簇（JD3/6/7）**：看重 Agent 平台架构、高并发高可用、Java / Spring Cloud、RAG（JD3）、微调（JD6）。该簇硬要 RAG / 微调。

两版核心经历相同，差异仅在**语序、强调、补一句、措辞**——维护成本极低，收益是命中率提升。

- **版 A：AI 负责人 / 一号位版（投 JD1/2/4/5）**
  - 标题 / 价值主张把 AI 身份前置；"鼓励不强推"改主动语态；强化 Agent 编排全链路与跨团队推广；百万并发标"规划 / 可迁移"；不强调微调短板（这些岗不硬要）。
- **版 B：AI 技术总监 / 架构版（投 JD3/6/7）**
  - 强化架构深度（token-hub / Spring Cloud / 高并发）；补 RAG/Memory 一句；补 AI 技术栈关键词；JD6 微调若为硬门槛，要么补"规划中"要么单独决定是否投。

> 注：版 A / 版 B 不是"两套经历"，是"同一经历两种讲述"。建议先出通投母版（含 P0/P1 改动），再派生两版微调。
