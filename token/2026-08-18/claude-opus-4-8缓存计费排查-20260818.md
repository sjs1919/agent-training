## ⚠️ 计费异常（重点，待修复）

### 反推出的线上公式

线上版本（镜像 20260805）扣额公式（对 728 / 747 等记录逐分精确匹配）：

```
额度 = max(0, prompt_tokens − cache_tokens(读) − cache_write_tokens) × model_ratio
      + cache_tokens × cache_read_ratio
      + completion_tokens × completion_ratio
      + cache_write_tokens × cache_write_ratio
```

### 问题本质

公式假设 `prompt_tokens` 是"总输入"（含缓存部分），所以要减掉缓存读/写再按满倍率计费——这对 **OpenAI 协议正确**（OpenAI 的 `prompt_tokens` 含 cached tokens）。

但对 **Claude 协议错误**：Claude Messages API 的 `input_tokens` **本就不含** `cache_creation_input_tokens` 和 `cache_read_input_tokens`。再减一次 cache_write 就会把"新输入"扣成负数→0，**新输入被免单**。

### 本次影响（调用2）

- `max(0, 15610 − 0 − 34950) = 0` → 15,610 个新输入未计费。
- 应扣：15610×11.6667 + 34950×14.5833 + 122×58.3333 = **698,920.18**
- 实扣：34950×14.5833 + 122×58.3333 = **516,803.00**
- **漏收 ≈ 182,117 额度 ≈ ¥0.55**（tokens_per_yuan=333,333.34，已变更，非默认 500）
